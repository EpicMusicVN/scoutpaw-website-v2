Path to 100 — Operations Prep

The code is shipped; the striped gap to 100 is content, assets, and information only the Ops / content / design team can supply. Each item below is tagged with the score it lifts. Full tick-list: ops-prep-checklist.md.

🧩 Why "updating context" moves the score

The builders in lib/seo are generic by design — they emit whatever the content adapter (faq.json, site-config.json, Video/Product models) and env vars feed them. They can't invent facts. The shipped code already renders every schema, OG tag, and sitemap entry; what caps the score now is placeholder-grade inputs. "Updating context" = swapping placeholders for real, unique, verified data — the same machinery then emits high-quality signals automatically. No further code change required.

Proof in code: structured-data.ts:100 ships every VideoObject.description as "{title} — a calming video from ScoutPaw TV." The field is wired; the data isn't. Supply real descriptions → the same builder emits a strong signal.

AContent lifts On-Page + AEO. Ranking and answer engines reward unique, deep, factual text — they literally quote it. Thin/visual pages give nothing to cite. Depth = citability.
BAssets lift Social + Schema. Organization.logo and OG cards need correctly-sized images with declared dims. Today banner.png is the wrong ratio → broken share previews, weak brand entity.
CData lifts Structured Data. Real business facts turn empty/optional schema fields into rich results — social graph (sameAs), live product data, truthful lastmod dates.
DConfig lifts Technical + AEO. Submission + canonical host is how engines discover and trust everything above. Bing (D4) powers ChatGPT search → direct AEO value.
